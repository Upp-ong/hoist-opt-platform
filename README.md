# 装配式地铁车站吊装调度与可视化决策平台

基于项目说明书实现的 Python 可视化原型，覆盖：

- 深圳地铁 14 号线、青岛地铁 6 号线、长春地铁 2 号线参数化工程场景
- 预制构件布置、重量、风险、前置约束与吊装设备能力校验
- NSGA-II 非支配排序、拥挤距离筛选、Pareto 前沿与多目标迭代
- 基于构件尺寸与标准截面的简化 BIM 三维场景，包含拱形顶板、I 形梁、带肋板和踏步楼梯
- 三维状态播放、楼层过滤、风险着色和相机视图
- 底板采用向下凸拱，两块水平站台板在车站中心附近靠拢，中间保留约 1.5m 中柱贯通槽
- 站台板安全突起按左右方向生成，左侧突起朝左，右侧突起朝右
- 底板按三排连续铺满车站横向宽度，每一纵向位置均包含完整的三排底板
- 只保留中轴一排预制立柱，中纵梁直接支承在立柱顶部
- 中板下移以扩大上层站厅空间，中柱向下延伸至底板面
- 右侧保留少量中板并设置站台层至站厅层楼梯洞口
- 楼梯按层高自动生成约 12-36 级踏板和踢面，并显示踏步前缘及两侧梯段控制线
- 三维总览默认使用本地 Three.js 查看器，支持拖拽旋转、缩放、构件拾取和客户端进度播放
- Three.js 运行库已固化在项目中，不依赖 npm 或浏览器外部 CDN
- 三维构件默认使用不透明实体渲染，避免进度达到 100% 时因透明面和全局边线造成视觉混乱
- 构件之间保留轻微几何缩缝，最近安装的 12 件构件持续保留细轮廓，当前件和下一件使用粗高亮
- 进度 0% 时使用类型色定位点表示全部计划位置，不渲染实体细节；随后按吊装顺序逐件转为实体，已完成构件持续保留
- 吊装进度增加后，已安装构件保留实体和结构轮廓，当前及下一件高亮显示
- 吊装设备按双轨龙门吊建模，自动推导轨道长度、主梁跨度、小车行程和最大起升高度
- 优化时间按大车纵向行走、小车横向行走、吊钩升降和安装时间组合计算
- 吊装甘特计划、成本结构、风险定位和八因子风险贡献分析
- 进度优先、成本优先、安全优先与综合推荐四类决策方案
- 决策模式使用三目标和 NSGA-II；专业模式使用工期、成本、空间碰撞、作业环境、设备均衡五目标和 NSGA-III
- 专业模式包含目标体系、平行坐标、目标投影、风险分解、权重敏感性、算法审计和模式对比
- 成本按每台龙门吊实际占用时长分别计算；进度、成本、安全三类方案互斥选取不同 Pareto 解
- 标准化 CSV/XLSX 构件导入、模板下载、逐行校验和 BOM/吊装调度导出
- 项目中心支持示例项目、参数化新建、导入项目和本地项目保存/重新打开
- 项目包保存构件、关系、设备和项目参数为独立 JSON，打开后自动重建并重新优化

## 启动

```powershell
python -m pip install -r requirements.txt
.\run_app.ps1
```

浏览器访问 `http://localhost:8501`。

也可以直接运行：

```powershell
python -m streamlit run app.py --server.port 8501
```

## 测试

```powershell
python -m unittest discover -s tests -v
```

```text
hoisting/domain.py       参数化构件、前置关系与数据校验
hoisting/optimizer.py    多目标优化与吊装调度评估
hoisting/charts.py       Plotly 三维场景和决策图表
hoisting/presentation.py 页面样式、指标与导出数据格式
hoisting/three_viewer.py Three.js 场景数据生成与嵌入
tests/test_platform.py   核心逻辑测试
```

## 数据导入格式

Excel 模板包含四张工作表：

```text
项目参数
构件数据
构件关系
设备数据
```

其中“构件数据”为必需表，其余三张表可选。CSV 用于只导入构件数据。

每一行“构件数据”代表一件预制构件。必填字段如下：

| 字段 | 说明 |
| --- | --- |
| 构件编号 | 全局唯一，用于前置关系和结果回写 |
| 语义类型 | 项目实际使用的构件名称，例如顶纵梁、中纵梁、仰拱、PC立柱 |
| 几何族 | 可选；板、梁、柱、墙、拱板、楼梯、自定义，不填时按语义类型推断 |
| 构件名称 | 现场识别名称 |
| X坐标(m)、Y坐标(m)、Z坐标(m) | 统一工程坐标系及标高基准 |
| 重量(t) | 用于设备起重能力校核 |
| 安装时长(min) | 对位、就位和临时固定时间 |
| 构件长(m)、构件宽(m)、构件高(m) | 用于空间碰撞、净空和迎风面积计算 |
| 障碍等级 | `0-3`，数值越大表示作业空间越复杂 |
| 作业可视性 | `0` 直接可见、`1` 部分遮挡、`2` 盲吊 |
| 地基条件 | `0` 良好、`1` 一般、`2` 较差 |
| 重心高度(m) | 可选，不填写时按构件高度的一半计算 |
| 旋转要求 | 可选，`0` 不需要翻身、`1` 需要旋转或翻身 |
| 前置构件编号 | 可选，多个编号使用分号分隔，例如 `C001;C002` |

“构件关系”表支持前置、支承、连接、闭合和对称关系。“设备数据”表可配置龙门吊额定能力、轨道范围、小车行程、起升高度、速度和费用；不填写时系统根据车站几何自动推导。

系统不再要求人工填写风险指数，而是根据构件重量、设备能力、坐标、尺寸、障碍等级、可视性、地基条件、风荷载和旋转要求自动计算。页面会同时展示综合风险及各项风险贡献。系统还会检查字段缺失、非数值、编号重复、几何族、异常重量或坐标、缺失前置构件和循环依赖。校验通过后，可点击“应用导入数据并重新优化”，导入构件将直接进入三维视图和 Pareto 求解流程。

## 工程说明

当前版本用于竞赛展示和算法联动验证。三维总览默认采用浏览器端 Three.js，Plotly 保留为兼容视图。决策模式使用工期、成本、综合安全三目标和 NSGA-II；专业模式使用工期、成本、空间碰撞、作业环境、设备均衡五目标和 NSGA-III。两种模式共享构件、龙门吊和前置约束数据。后续可将 Excel 模型与 IFC、GLB、DWG/DXF 或 SolidWorks 导出模型关联。
